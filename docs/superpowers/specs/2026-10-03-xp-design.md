# Portail Personnages MET — Sous-projet 4 : Expérience (XP)

Date : 2026-10-03
Statut : validé en conversation, en attente de relecture
Dépend de : sous-projet 1, Socle (`2026-10-02-socle-design.md`) ; sous-projet 2, Fiche et création guidée (`2026-10-02-fiche-design.md`)
Maquettes :
- côté joueur : `J-XP`, `J-XP-Competence`, `J-Demandes`, `J-Rachat` ;
- côté conteur : `C-Validation`, `C-XP`, `C-Correction`, `C-Parametres` (partie Expérience).

Toutes existent en Web 1440 et Mobile 390.

## Objectif

Faire évoluer une fiche active par l'XP, sans code serveur (formule Spark) :

- le joueur dépense son XP par des **demandes**, validées par un conteur ;
- un conteur attribue des **bonus ponctuels** et fait des **corrections** (remboursement, annulation, rachat forcé avec dette) ;
- un conteur **verse le gain mensuel**, préparé par l'application selon des paliers d'ancienneté ;
- un conteur règle le gain mensuel dans les **paramètres d'expérience**.

## Décisions

1. **Gain mensuel préparé, puis versé par un conteur.** Sans Cloud Functions, rien ne part seul le 1er du mois. L'application calcule les montants dus, le conteur les vérifie et les verse. Les mois oubliés se rattrapent au versement suivant.
2. **Les demandes vivent dans une collection `requests` à part.** La fiche n'est modifiée qu'à la validation : pas de faux conflit de version pendant l'attente.
3. **L'XP réservée se calcule** : c'est la somme des demandes ouvertes, rien n'est écrit sur la fiche. La dette est simplement une XP disponible négative. Les gains suivants la remboursent d'eux-mêmes.
4. **Bonus, gains, corrections et validations sont des éditions de fiche par un conteur.** Elles réutilisent la règle `staffEdit` du sous-projet 2 : motif obligatoire, historique, et jamais sur sa propre fiche. Seuls de nouveaux types d'entrée d'historique s'ajoutent.
5. **Décident :** les conteurs et le principal. Le narrateur voit sans agir.

## Modèle de données

### `requests/{id}` (demande d'XP)

```
characterId: string
characterName: string        // copie, pour les listes
playerUid: string
playerName: string
status: 'draft' | 'pending' | 'changes' | 'accepted' | 'rejected' | 'cancelled'
items: [{ kind, name, fromLevel, toLevel, cost, note }]
  kind : 'attribute' | 'skill' | 'background' | 'discipline' | 'merit' | 'humanity' | 'flawBuyback'
  name : nom du trait (pour un attribut : 'physical' | 'social' | 'mental')
  note : précision (domaine, détail d'historique), ou null
total: int                   // somme des cost
justification: string
thread: [{ byUid, byName, at, text }]   // échanges joueur ↔ conte
createdAt, updatedAt, submittedAt, decidedAt: timestamp | null
decidedByUid: string | null
version: int                 // +1 à chaque écriture
```

Libellés des statuts (FR) : Brouillon, En attente, À compléter, Validée, Refusée, Annulée.

- `merit` : `fromLevel` vaut 0 et `toLevel` la valeur de l'atout.
- `flawBuyback` : `fromLevel` vaut la valeur du handicap et `toLevel` vaut 0.

### Fiche (`characters/{id}`)

- Nouveau champ `gainedThrough: string | null`, au format `'aaaa-mm'` : le dernier mois de gain mensuel versé.
- XP disponible = `xpInitial + xpEarned − xpSpent` (existant). Elle peut être négative : c'est la dette.

### Historique (`characters/{id}/history/{h}`)

Nouveaux `kind` :

| kind | Libellé | Effet XP |
|---|---|---|
| `xp` | Dépense d'XP | `spent` + total, traits modifiés |
| `award` | Bonus d'XP | `earned` + n |
| `gain` | Gain mensuel | `earned` + n |
| `correction` | Correction d'XP | `earned` ou `spent`, selon le type ; traits modifiés pour une annulation ou un rachat forcé |

- `bonus` reste le bonus de création du sous-projet 2.
- Le filtre « Statut » de l'historique exclut ces nouveaux types. Le filtre « XP » les montre (`touchesXp`).
- `reason` (le motif) :
  - `xp` : « Demande validée » suivi du commentaire du conteur, s'il y en a un ;
  - `award` et `correction` : le motif saisi ;
  - `gain` : « Gain mensuel · oct. 2026 » (plusieurs mois : « Gain mensuel · sept.–oct. 2026 »).

### `chronicle/xp` (paramètres)

```
monthlyEnabled: bool          // défaut false
gainSince: string             // 'aaaa-mm', premier mois versé
tiers: [{ months: int | null, xp: int, every: int }]
  // dans l'ordre ; months = durée du palier en mois ; null = sans limite (dernier palier seulement)
updatedAt, updatedByUid, updatedByName
```

Paliers par défaut (maquette) :

| Palier | Durée | Gain |
|---|---|---|
| 1 | 36 mois | 3 XP tous les mois |
| 2 | 36 mois | 2 XP tous les mois |
| 3 | 24 mois | 1 XP tous les mois |
| 4 | sans limite | 1 XP tous les 2 mois |

## Règles de calcul (`lib/xp/xp_rules.dart`, pur, testé)

### Coûts après la création

Ils dépendent du rang actuel de la fiche (`genRank`, Neonate par défaut).

| Achat | Coût du niveau n | Plafond |
|---|---|---|
| Attribut | 3 | 10 |
| Compétence | n × 1 (Neonate) ou n × 2 (Ancilla, Pretender) | 5 |
| Historique (sauf Génération) | n × 1 ou n × 2, comme une compétence | 5 |
| Discipline en clan | n × 3 | 5 |
| Discipline hors clan | n × 4 | 5 |
| Atout | sa valeur (`baseMerits`) | 7 points d'atouts au total, rareté de clan comprise |
| Humanité | 10 par point | 6 (livre de base p. 300) |
| Rachat d'un handicap | 2 × sa valeur | — |

- **Génération :** elle ne s'achète pas.
- **Précision obligatoire (`note`)**, et message bloquant si elle manque :
  - pour un nouveau point d'historique ;
  - pour le premier point d'Artisanat, de Représentation ou de Sciences (le domaine) ;
  - pour chaque point supplémentaire de ces trois compétences (un nouveau domaine).
- **Discipline hors clan :** possible, avec l'avertissement « Professeur nécessaire : à confirmer par le conte » (livre de base p. 108 : toute discipline hors clan achetée avec l'XP gagnée demande un professeur).
- **Plusieurs niveaux d'un même trait** s'empilent dans une demande : `fromLevel` du second = `toLevel` du premier.
  - Le retrait se fait par le haut. Retirer un niveau inférieur affiche « Retirez d'abord le niveau supérieur ».

### XP disponible et réservée

- `available(c)` = `xpInitial + xpEarned − xpSpent`.
- `reserved(c, requests)` = somme des `total` des demandes de la fiche en `pending` ou `changes`, la demande en cours d'édition exclue.
  - Côté joueur, `requests` vient de ses propres demandes (requête `playerUid == moi`, filtrée sur la fiche dans l'application) : les règles refusent à un joueur une requête sur `characterId` seul.
  - Côté conteur, une requête `characterId` + `status`.
- `usable` = `available − reserved`.
- Un achat qui ferait dépasser `usable` est refusé : « XP libre insuffisante : N requis, M restant après les achats déjà ajoutés. »

### Contrôles d'une demande à la validation (`requestChecks`)

| Contrôle | Niveau |
|---|---|
| Niveau actuel de la fiche ≠ `fromLevel` : « La fiche a changé : Auspex est à ●●● (demande faite depuis ●●) » | erreur ; « Valider » désactivé |
| Coût recalculé ≠ coût envoyé (le rang a changé) : « Coût recalculé : 6 XP au lieu de 4 » | avertissement ; la validation applique le coût recalculé |
| XP restante après validation < 0 : « Dette après validation : N XP » | avertissement |
| Plafond dépassé, ou atouts > 7 | erreur |
| Discipline hors clan non commune | avertissement |

### Gain mensuel (`monthlyGain`)

- **Fiches concernées :** les PJ actifs (`kind == pj`, `status == active`).
- **Activation :** le mois de `creation.decidedAt`, à défaut celui de `createdAt`.
- **Fuseau :** tous les mois se calculent en UTC (mois courant, activation), pour que chaque appareil voie les mêmes mois ; la bascule se fait à 1 h ou 2 h du matin, heure de Paris.
- **Mois dus :** de `max(gainedThrough + 1, gainSince, mois d'activation + 1)` jusqu'au mois courant inclus.
  - Le mois d'activation ne donne rien : une fiche activée le 31 touche son premier gain le 1er du mois suivant.
- **Montant d'un mois m :**
  - ancienneté `a` = nombre de mois entre le mois d'activation et m (≥ 1) ;
  - palier = celui qui couvre `a` (cumul des `months`) ;
  - gain = `xp` si `(a − début du palier) % every == 0`, sinon 0.
  - Le premier mois d'un palier compte : « tous les 2 mois » paie au 1er, 3e, 5e… mois du palier.
- **Résultat par fiche :** les mois dus, le total, et le dernier mois (le nouveau `gainedThrough`).
  - Une fiche sans mois dû n'apparaît pas.
  - Une fiche dont les mois dus totalisent 0 XP voit quand même son `gainedThrough` avancer.
- **Gain désactivé :** rien n'est dû.

## Écrans du joueur

### « Mes demandes » (`/joueur/demandes`, J-Demandes)

- **En-tête :**
  - Titre « Mes demandes », et le sous-titre « Toutes les évolutions de vos fiches passent par ici avant d'être validées par le conte. »
  - Bouton « Dépenser de l'XP ». S'il y a plusieurs PJ actifs, un menu choisit le personnage. Sans PJ actif, le bouton est désactivé, avec « Aucun personnage actif ».
- **Onglets :** « Toutes · N », « En cours · N » (brouillon, en attente, à compléter) et « Traitées · N » (validée, refusée, annulée).
- **Tableau :** type (« Dépense XP », ou « Création » pour une fiche en création, en lecture seule, avec un lien vers la fiche), objet, personnage, date, statut.
  - L'objet est la liste courte des achats, par exemple « Linguistique ●● et Mental 6 · 7 XP ».
  - Le tri est du plus récent au plus ancien.
- **Détail** (panneau à droite en Web, page `/joueur/demandes/:id` sur mobile) :
  - type, statut, objet, personnage, date d'envoi ;
  - les achats (de → à, coût), le total ;
  - la justification, puis le fil d'échanges (le conte sur fond accentué) ;
  - « Votre réponse » (obligatoire), « Renvoyer au conte » et « Annuler la demande » pour une demande à compléter ;
  - « Modifier » et « Annuler la demande » pour un brouillon ou une demande en attente ;
  - la note « Les N XP restent réservés tant que la demande est ouverte. » pour une demande ouverte ;
  - l'annulation demande une confirmation.
- **Vide :** « Aucune demande pour l'instant. »

### « Dépenser de l'XP » (`/joueur/personnages/:id/xp`, et `?demande=<id>` pour modifier)

- **Fil d'Ariane :** « [Personnage] / Nouvelle demande » (ou « Modifier la demande »).
- **Titre :** « Dépenser de l'XP ».
- **Sous-titre :** « Le coût est calculé selon la génération du personnage ([rang]). L'XP est réservée jusqu'à la décision du conte. »
- **Section « Ajouter un achat » :**
  - **Type :**
    - Attribut, Compétence, Historique, Discipline, Atout, Humanité ;
    - « Rachat d'un handicap », qui remplace l'écran J-Rachat. Il affiche « Coût : 2 fois la valeur du handicap · accord du conte obligatoire ».
  - **Élément :**
    - pour une compétence, la fiche puis la liste, et « Autre… » ;
    - pour une discipline, celles de la fiche puis les communes, et « Autre… » ;
    - pour un atout, ceux qui ne sont pas encore pris ;
    - pour un rachat, les handicaps de la fiche.
  - **Niveau** de → à, et **coût** avec sa règle (« 2 × 3 »).
  - Champ **précision** quand elle est obligatoire, avec un libellé selon le cas : « Domaine », « Détail du nouveau point ».
  - Message d'erreur sous le bouton : XP insuffisante, plafond atteint, précision manquante.
  - Bouton « Ajouter à la demande ».
- **« Contenu de la demande » :**
  - tableau : achat, évolution, règle, coût, retirer ;
  - total ;
  - vide : « Aucun achat pour l'instant. »
- **Justification :** « Justification en jeu (visible par le conte) », avec le texte d'aide « Comment le personnage a-t-il appris ou progressé ? ». Obligatoire pour envoyer.
- **Boutons :**
  - « Annuler » : retour sans enregistrer, avec confirmation s'il y a des changements ;
  - « Enregistrer le brouillon » : actif dès qu'il y a un achat ;
  - « Envoyer au conte · N XP » : actif s'il y a au moins un achat et une justification.
  - **Après l'envoi ou l'enregistrement :** retour à « Mes demandes », avec la demande sélectionnée.
- **Panneau latéral :**
  - « Solde d'XP » : Disponible, Réservé (une ligne par demande ouverte), Cette demande, puis « Restera libre » en grand ;
  - « Coûts pour un [rang] » : le tableau des coûts ;
  - la note « La Génération et les atouts de lignée ne s'achètent qu'à la création. »
- **Accès :**
  - seulement le joueur de la fiche, et seulement si elle est active ;
  - sinon, l'état « Accès refusé » ou « Cette fiche n'est pas active », avec un lien vers la fiche ;
  - une demande validée, refusée ou annulée ne se modifie pas : retour au détail.
- **Modification d'une demande :**
  - en attente : elle reste en attente ;
  - à compléter : « Envoyer au conte » la repasse en attente ;
  - si la demande a changé entre-temps (version), le message « La demande a été traitée entre-temps » s'affiche et l'écran revient au détail.

### Points d'entrée

- **Fiche du joueur (J2), PJ actif :** bouton « Dépenser de l'XP ». La fiche affiche aussi « XP utilisable : N (dont M réservés) ».
- **Carte personnage (J1), PJ actif :** l'XP disponible, et « N demandes en cours » vers « Mes demandes ».
- **Onglet « Mes demandes » de la coquille joueur :** il remplace l'état « À venir ».

## Écrans du conteur

### « Demandes » (`/conteur/demandes`, C-Validation étendu)

- **File** « En attente · N » : créations en `review` et demandes d'XP en `pending`, de la plus ancienne à la plus récente.
  - Filtre : « Tous les types », « Créations », « Dépenses d'XP ».
  - Chaque ligne affiche le type (couleur des maquettes), la date, le personnage et l'objet.
- **Création :** inchangé (sous-projet 2).
- **Dépense d'XP :**
  - **En-tête :** badge « Dépense XP », « Envoyée le … par [joueur] », le nom du personnage, son clan, sa secte, son rang.
  - **Solde :** « Disponible N · Réservé par d'autres demandes M · Cette demande T · Après validation R ». R est en rouge s'il est négatif.
  - **Achats :** tableau (achat, de → à, coût, règle).
  - **Contrôles automatiques :** `requestChecks`.
  - **Justification et fil d'échanges.**
  - **« Commentaire au joueur »** : obligatoire pour des compléments ou un refus. Message : « Expliquez ce qu'il faut compléter. »
  - **Boutons :**
    - **« Valider la dépense »** : désactivé tant qu'un contrôle est en erreur. Il écrit dans un même lot :
      - la fiche : traits à `toLevel` (atout ajouté, handicap retiré, Humanité), `xpSpent` + total recalculé, version + 1 ;
      - l'entrée d'historique `xp` ;
      - la demande : statut `accepted`, `decidedAt`, `decidedByUid`, et le commentaire ajouté au fil s'il n'est pas vide.
    - **« Demander des compléments »** : statut `changes`, commentaire ajouté au fil.
    - **« Refuser »** : confirmation, statut `rejected`, commentaire ajouté au fil.
  - **Après une décision :** le commentaire est vidé et la sélection passe à la demande suivante.
- **Droits :**
  - **Demande sur sa propre fiche :** le conteur lit « C'est votre propre fiche : un autre conteur doit la valider. » et ne voit aucun bouton.
  - **Narrateur :** la file et le détail, sans commentaire ni boutons, avec la mention « Lecture seule : les conteurs décident. » La même règle s'applique aux créations.
- **Vide :** « Aucune demande en attente ».

### « XP » (`/conteur/xp`, C-XP)

- **Titre :** « Expérience », avec le lien « Corrections et remboursements ».
- **Carte « Gain mensuel »** :
  - Désactivé : « Gain mensuel désactivé », avec un lien vers les paramètres.
  - Rien de dû : « À jour : dernier versement [mois] ».
  - Sinon :
    - « [Mois] : N fiches, X XP à verser » ;
    - « Voir le détail » liste chaque fiche : personnage, joueur, mois dus, palier, XP ;
    - « Verser X XP », avec confirmation.
  - **Le versement :**
    - une écriture par fiche, en lots de 200 fiches au plus : fiche (`xpEarned` + n, `gainedThrough`, version + 1) et entrée `gain` ;
    - les fiches du conteur sont exclues et listées : « À verser par un autre conteur : [noms] » ;
    - une fiche refusée (modifiée entre-temps, ou déjà versée par un autre conteur) est signalée. Les autres sont versées, et l'écran recalcule.
- **« Attribuer un bonus d'XP »** :
  - **Saisie :**
    - « Motif » (obligatoire, par exemple « Bonus — scène de la Cour du 17 octobre ») ;
    - « XP par fiche » (− / +, de 1 à 100, 1 par défaut) ;
    - « Appliquer à la sélection ».
  - **Liste des PJ actifs :**
    - colonnes : sélection, personnage, joueur, XP disponible, ajout (modifiable par ligne), après ;
    - recherche par nom, « Tout sélectionner · PJ actifs (N) » ;
    - les fiches du conteur sont grisées, avec l'infobulle « Votre propre fiche ».
  - **Récapitulatif :** fiches sélectionnées, dont montant ajusté, XP distribuée, motif.
  - **« Attribuer à N fiches »** : confirmation, puis une écriture par fiche (`xpEarned` + n, entrée `award`).
    - Les fiches refusées sont signalées, comme pour le versement.
    - Le bouton est désactivé sans motif ou sans sélection.

### « Corrections » (`/conteur/xp/corrections`, C-Correction)

- **Titre :** « Corrections et remboursements », avec le sous-titre « Rien ne s'efface : chaque correction ajoute une ligne à l'historique de la fiche, avec son motif. »
- **« Dernières corrections » :**
  - Les 20 entrées `correction` les plus récentes, toutes fiches confondues : date, fiche, type, motif, XP, auteur.
  - C'est une requête sur les historiques de toutes les fiches (`collectionGroup('history')`), filtrée sur `kind == correction` et triée par `at` décroissante. Elle demande un index.
- **« Nouvelle correction » :**
  - **Fiche** (PJ et PNJ, sauf les siennes), puis **Type** :
    - « Correction d'une erreur de coût » : montant à rendre (+) ou à reprendre (−), sur `xpSpent` ;
    - « Remboursement (règle changée, élément retiré) » : montant à rendre, sur `xpSpent` ;
    - « Annulation d'un achat » :
      - on choisit un achat parmi les demandes validées de la fiche (« Vigilance ●●● · achat du 12 sept. · 6 XP ») ;
      - le trait revient à `fromLevel` (atout retiré, handicap racheté remis) et `xpSpent` diminue du coût ;
      - si le niveau actuel n'est plus `toLevel`, c'est bloquant : « Le trait a changé depuis : corrigez-le dans la fiche. » ;
    - « Rachat forcé d'un handicap » : on choisit un handicap de la fiche ; il est retiré et `xpSpent` augmente de 2 × sa valeur.
  - **Aperçu :** « À rendre : + 3 XP » ou « À payer : − 4 XP · dette de 2 XP » quand l'XP disponible devient négative.
  - **Motif** (obligatoire), avec la note « Visible par le joueur dans son historique ».
  - **« Enregistrer la correction »** : une écriture (fiche, version + 1, entrée `correction`).

### « Paramètres d'expérience » (`/conteur/parametres/xp`, C-Parametres)

- **Navigation :** `/conteur/parametres` affiche le menu des paramètres (Expérience ; les autres entrées restent « À venir »).
- **Accès :** conteurs et principal. Le narrateur voit l'état « Accès refusé ».
- **« XP de création »** : XP de départ 30, maximum via handicaps 7, maximum mis de côté 5, en lecture seule, avec la note « Modifiables avec le référentiel des règles (à venir) ».
- **« Gain mensuel d'XP »** :
  - interrupteur « Activé » ;
  - « Versé à partir de » (mois) ;
  - le rappel « PJ actifs uniquement (ni PNJ, ni brouillons). Préparé par l'application, versé par un conteur. »
- **« Paliers selon l'ancienneté »** :
  - tableau : palier, pendant (années), gain (XP), tous les (mois), soit par an ;
  - le dernier palier affiche « Ensuite, sans limite » ;
  - « + Ajouter un palier » et retrait d'un palier (au moins un palier) ;
  - contrôles : nombres entiers, XP de 0 à 20, « tous les » de 1 à 12, durée de 1 à 50 ans ;
  - cumuls « Après 1 an / 3 ans / 6 ans / 8 ans / 10 ans ».
- **Boutons :**
  - « Annuler » : revient aux valeurs enregistrées ;
  - « Enregistrer » ;
  - la note « Les changements s'appliquent aux versements futurs ; l'XP déjà versée ne change pas. » ;
  - « Dernière modification par … le … ».

## Sécurité (`firestore.rules`)

- **`requests/{id}` :**
  - **Lecture :** `resource.data.playerUid == auth.uid`, ou `isStaff()`.
  - **Création par le joueur :**
    - `playerUid == auth.uid` ;
    - la fiche `characterId` existe, a `playerUid == auth.uid` et `status == 'active'` ;
    - `status in ['draft', 'pending']`, `version == 1` ;
    - `decidedAt`, `decidedByUid` nuls.
  - **Mise à jour par le joueur** (`resource.data.playerUid == auth.uid`) :
    - `version == old + 1` ;
    - `old.status in ['draft', 'pending', 'changes']` et `new.status in ['draft', 'pending', 'cancelled']` ;
    - `characterId`, `playerUid`, `decidedAt`, `decidedByUid` et `createdAt` inchangés.
  - **Décision** par `managesAccounts()`, si la fiche n'est pas la sienne :
    - `version == old + 1`, `old.status == 'pending'`, `new.status in ['changes', 'rejected', 'accepted']` ;
    - seuls changent `status`, `thread`, `decidedAt`, `decidedByUid`, `updatedAt` et `version` ;
    - `changes` et `rejected` : `thread` gagne exactement un message, écrit par l'auteur et non vide ;
    - `accepted` : la fiche change de version dans le même lot (`getAfter(fiche).version == get(fiche).version + 1`).
  - **Suppression :** jamais.
- **`characters/{id}` :**
  - `staffEdit` accepte les `kind` `['edit', 'status', 'xp', 'award', 'gain', 'correction']`, motif non vide.
  - `playerDraftSave` protège en plus `gainedThrough`.
- **`chronicle/xp` :** lecture si connecté, écriture par `managesAccounts()`.
- **Historique de toutes les fiches** (`match /{path=**}/history/{h}`) : lecture par `isStaff()`, pour la liste des corrections.
- **Index** (`firestore.indexes.json`) :
  - `history` (groupe de collections) : `kind` ASC, `at` DESC ;
  - `requests` : `characterId` ASC, `status` ASC ;
  - `requests` : `playerUid` ASC, `createdAt` DESC.

Les règles ne vérifient ni les coûts ni les montants : le conteur est de confiance, et les contrôles sont affichés avant chaque décision.

- **Application d'une dépense, réutilisée par la validation et l'annulation d'achat :** `applyItems(Character, List<XpItem>)`, qui renvoie un clone modifié.

## Cas à vérifier à la revue

1. Le conteur modifie la fiche (C3) pendant qu'une demande attend : à la validation, l'écart est affiché et la validation est bloquée, jamais appliquée à l'aveugle.
2. Deux conteurs versent le gain mensuel en même temps : la version de chaque fiche empêche un double versement.
3. Une correction rend l'XP négative alors qu'une demande attend : la dette apparaît dans les contrôles de la demande.
4. Le joueur modifie une demande en attente pendant que le conteur la valide : une des deux écritures est refusée (version de la demande), et jamais une version différente de celle affichée n'est appliquée.
5. Une fiche activée le 31 du mois : pas de gain ce mois-là, un seul le mois suivant.
