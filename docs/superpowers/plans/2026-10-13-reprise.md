# Reprise de fiches existantes (sous-projet 10c) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** le conte crée un PJ (ou une goule jouée) directement actif, « Fiche existante (reprise) », puis le recopie dans l’éditeur C3 existant.

**Architecture :** une branche de plus dans la règle `create` de `characters` (PJ en `active`), un paramètre `resumed` sur `CharacterRepository.create`, une case à cocher dans `NewCharacterDialog`. Aucun nouvel écran, aucun nouveau fichier de code.

**Tech Stack :** Flutter, Riverpod 3, Cloud Firestore, tests de règles Node (`@firebase/rules-unit-testing`).

**Spec :** `docs/superpowers/specs/2026-10-13-reprise-design.md`

## Global Constraints

- Textes : apostrophe typographique ’, espace avant `:`.
- Ne pas lancer `dart format` ; fins de ligne LF.
- `flutter analyze` propre, `flutter test` et les tests des règles verts.
- Ne jamais committer `bash.exe.stackdump`, `rules_test/bash.exe.stackdump`, `firestore-debug.log`, `rules_test/firestore-debug.log`.
- Libellé de la case : « Fiche existante (reprise) », clé `new-resume`.
- Aide, case cochée : « La fiche est active tout de suite, sans création guidée : vous la recopiez ensuite dans l’éditeur. »
- Historique : « Fiche reprise », ou « Fiche de goule reprise ».

## Review Focus

1. Case cochée puis type passé à PNJ : la création ne doit pas transmettre `resumed` (un PNJ l’ignore déjà, mais le dialogue ne l’envoie pas non plus). Test dans la tâche 2.
2. Un conte qui crée un PJ actif pour lui-même : refusé par les règles, comme le brouillon. Test dans la tâche 1.
3. Un narrateur qui crée un PJ actif : refusé. Test dans la tâche 1.
4. Case cochée : le joueur reste obligatoire (« Choisissez le joueur. »). Test dans la tâche 2.
5. Dialogue à 390 px de large avec la case : pas de débordement. Test dans la tâche 2.
