# Journal de la chronique (sous-projet 10b) : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** une page « Journal de la chronique » (conteur et principal) qui liste ce que le conte et l'application ont modifié, avec filtres et export CSV.

**Architecture :**
- **Calcul pur** dans `lib/journal/journal_rules.dart` :
  - lignes calculées à partir des historiques, des versions du wiki et des parties ;
  - fusion, filtres, période, CSV ;
  - notes à écrire dans `journal` (référentiel, comptes et rôles) et leur document.
- **Écritures :** `RulesRepository` (enregistrer, supprimer, importer) et `ChronicleRepository` (rôle, invitation) ajoutent une entrée `journal/{id}` dans le lot de l'action. La règle `journal` n'accepte que l'ajout.
- **Lecture :** `lib/journal/journal_repository.dart`. Requêtes par groupe de collections sur `history` et `versions`, plus `journal`, depuis le début de la période. `journalProvider(since)` assemble le tout, avec les noms (fiches, lieux, objets, alliés, serviteurs, comptes, pages).
- **Écran :** `JournalScreen` sur `/conteur/parametres/journal` ; entrée active dans les Paramètres.

**Tech Stack :** inchangée.

**Spec :** `docs/superpowers/specs/2026-10-13-journal-design.md`.

**Maquettes :** `C-Journal`, `C-Journal-mobile`.

- **Écarts avec la spec, relevés dans le code :**
  - **Gain mensuel :** `payGain` écrit un lot par fiche, donc les entrées n’ont pas le même `at`. Le regroupement se fait par motif (« Gain mensuel · {mois} ») et par auteur.
  - **Éléments hors fiches :** l’action est le type de l’élément (« Lieu », « Objet », « Allié », « Goule ou serviteur ») plutôt que « Modification », comme « Wiki » ou « Référentiel » dans la maquette.
  - **Partie levée :** une partie levée donne une deuxième ligne, « Gel levé ».
  - **« Depuis la dernière partie » :** la période part du jour de la dernière partie déjà jouée (`date` antérieure ou égale à aujourd’hui). Une partie figée mais pas encore jouée ne compte pas. L’option est absente s’il n’y en a pas.
  - **Bonus du conte :** le `kind` `bonus` va dans « XP ».
  - **Invitations :** elles n’ont pas de lien, car l’écran Équipe est réservé au principal et le journal est aussi lu par le conteur.
  - **Liens :** une ligne dont l’élément n’est plus connu (fiche, page supprimée) n’a pas de lien.

/// Catégories du journal ; le nom est la valeur stockée (`journal.cat`) pour `rules` et `accounts`.
enum JournalCat {
  sheets('Fiches'),
  xp('XP'),
  wiki('Wiki'),
  rules('Référentiel'),
  accounts('Comptes et rôles');

  const JournalCat(this.label);
  final String label;
}

enum JournalPeriod {
  days30('30 derniers jours'),
  sinceGame('Depuis la dernière partie'),
  all('Tout');

  const JournalPeriod(this.label);
  final String label;
}

String _who(String? name) => (name ?? '').trim().isEmpty ? 'Inconnu' : name!.trim();

/// Une ligne du journal : calculée (historiques, wiki, parties) ou lue dans `journal/{id}`.
class JournalLine {
  const JournalLine({required this.cat, required this.at, required this.who, required this.action, required this.target, required this.detail, this.link});

  /// L'heure est celle du serveur : absente de l'écho local de l'écriture, on prend celle de l'appareil.
  factory JournalLine.fromMap(Map<String, dynamic> m) => JournalLine(
        cat: JournalCat.values.asNameMap()[m['cat']] ?? JournalCat.accounts,
        at: (m['at'] as Timestamp?)?.toDate() ?? DateTime.now(),
        who: _who(m['byName'] as String?),
        action: m['action'] as String? ?? '',
        target: m['target'] as String? ?? '',
        detail: m['detail'] as String? ?? '',
        link: m['link'] as String?,
      );

  final JournalCat cat;
  final DateTime at;
  final String who;
  final String action;
  final String target;
  final String detail;

  /// Chemin de l'application ; null si l'élément n'est plus connu.
  final String? link;
}

/// Entrée d'historique lue par groupe de collections : `{col}/{parentId}/history/{h}`.
class RawHistory {
  const RawHistory({required this.col, required this.parentId, required this.at, required this.byName, required this.kind, required this.summary, required this.reason});
  final String col;
  final String parentId;
  final DateTime at;
  final String byName;
  final String kind;
  final List<String> summary;
  final String reason;
}

/// Version publiée d'une page du wiki : `wiki/{pageId}/versions/{n}`.
class RawVersion {
  const RawVersion({required this.pageId, required this.n, required this.title, required this.note, required this.byName, required this.at});
  final String pageId;
  final int n;
  final String title;
  final String note;
  final String byName;
  final DateTime at;
}

/// Écrites par le joueur : le journal trace les actes du conte.
const _playerKinds = {'submission', 'withdrawal'};
const _xpKinds = {'gain', 'award', 'xp', 'correction', 'bonus'};
const _kindLabels = {

  'validation': 'Validation',
  'corrections': 'Corrections demandées',
  'rejection': 'Fiche refusée',
  'embrace': 'Étreinte',

/// Collections qui ont un historique : (nom par défaut, liste du conte ; null pour une fiche).
const Map<String, (String, String?)> _owners = {
  'characters': ('Fiche', null),
  'places': ('Lieu', '/conteur/lieux'),
  'items': ('Objet', '/conteur/objets'),
  'allies': ('Allié', '/conteur/allies'),
  'servants': ('Goule ou serviteur', '/conteur/goules'),

String _detail(List<String> summary, String reason) => [...summary, if (reason.trim().isNotEmpty) 'Motif : ${reason.trim()}'].join(' ; ');

/// [names] : nom de chaque élément, par clé `'{col}/{id}'`.
/// Le gain mensuel écrit un lot par fiche : ses entrées sont regroupées par motif (le mois) et par auteur.
List<JournalLine> historyLines(List<RawHistory> rows, Map<String, String> names) {
  final out = <JournalLine>[];
  final gains = <(String, String), List<RawHistory>>{};
  for (final r in rows) {
    final owner = _owners[r.col];
    if (owner == null) continue;
    final sheet = r.col == 'characters';
    if (sheet && _playerKinds.contains(r.kind)) continue;

      continue;
    }
    final name = names['${r.col}/${r.parentId}'];
    out.add(JournalLine(
      cat: sheet && _xpKinds.contains(r.kind) ? JournalCat.xp : JournalCat.sheets,
      at: r.at,
      who: _who(r.byName),
      action: sheet ? _kindLabels[r.kind] ?? 'Modification' : owner.$1,
      target: name ?? owner.$1,
      detail: _detail(r.summary, r.reason),
      link: name == null ? null : (sheet ? '/conteur/fiches/${r.parentId}/historique' : owner.$2),
    ));
  }
  for (final g in gains.values) {
    out.add(JournalLine(
      cat: JournalCat.xp,
      at: g.map((r) => r.at).reduce((a, b) => a.isAfter(b) ? a : b),
      who: _who(g.first.byName),
      action: 'Gain mensuel',
      target: g.length == 1 ? '1 fiche' : '${g.length} fiches',

/// Lectures du journal : historiques et versions du wiki (groupes de collections, index `at` dans firestore.indexes.json)
/// et lignes stockées `journal/{id}`. Les écritures se font dans les dépôts du référentiel et des comptes.
class JournalRepository {
  JournalRepository(this._db);

  final FirebaseFirestore _db;

  // ponytail: 500 documents par source au plus ; paginer si une période en dépasse.
  static const cap = 500;

  Query<Map<String, dynamic>> _since(Query<Map<String, dynamic>> q, DateTime? since) =>
      (since == null ? q : q.where('at', isGreaterThanOrEqualTo: Timestamp.fromDate(since))).orderBy('at', descending: true).limit(cap);

  /// L'heure est celle du serveur : absente de l'écho local de l'écriture, on prend celle de l'appareil.
  static DateTime _at(Object? v) => (v as Timestamp?)?.toDate() ?? DateTime.now();

  Stream<List<RawHistory>> watchHistory(DateTime? since) => _since(_db.collectionGroup('history'), since).snapshots().map((q) => [
        for (final d in q.docs)
          if (d.data() case final m)
            RawHistory(
              col: d.reference.parent.parent!.parent.id,
              parentId: d.reference.parent.parent!.id,
              at: _at(m['at']),
              byName: m['byName'] as String? ?? '',
              kind: m['kind'] as String? ?? 'edit',
              summary: [for (final s in (m['summary'] as List?) ?? const []) '$s'],
              reason: m['reason'] as String? ?? '',
            ),
      ]);

  Stream<List<RawVersion>> watchVersions(DateTime? since) => _since(_db.collectionGroup('versions'), since).snapshots().map((q) => [
        for (final d in q.docs)
          if (d.data() case final m)
            RawVersion(
              pageId: d.reference.parent.parent!.id,
              n: int.tryParse(d.id) ?? 0,
              title: m['title'] as String? ?? '',
              note: m['note'] as String? ?? '',
              byName: m['byName'] as String? ?? '',
              at: _at(m['at']),
            ),
      ]);

  Stream<List<JournalLine>> watchStored(DateTime? since) =>
      _since(_db.collection('journal'), since).snapshots().map((q) => [for (final d in q.docs) JournalLine.fromMap(d.data())]);
}

@Riverpod(keepAlive: true)
JournalRepository journalRepository(Ref ref) => JournalRepository(ref.watch(firestoreProvider));

@riverpod
Stream<List<RawHistory>> journalHistory(Ref ref, DateTime? since) => ref.watch(journalRepositoryProvider).watchHistory(since);

@riverpod
Stream<List<RawVersion>> journalVersions(Ref ref, DateTime? since) => ref.watch(journalRepositoryProvider).watchVersions(since);

@riverpod
Stream<List<JournalLine>> journalStored(Ref ref, DateTime? since) => ref.watch(journalRepositoryProvider).watchStored(since);

/// Le fil d'une période. [partial] : une source a échoué (elle est absente) ; [loading] : une source charge encore.
class JournalFeed {
  const JournalFeed(this.lines, {this.partial = false, this.loading = false});
  final List<JournalLine> lines;
  final bool partial;
  final bool loading;
}

/// Une source qui charge ou qui échoue ne donne rien : elle n'empêche pas les autres.
List<T> _v<T>(AsyncValue<List<T>> a) => a.value ?? const [];

/// Journal depuis [since] (tout si null) : historiques, versions du wiki, parties et lignes stockées, avec les noms.
@riverpod
JournalFeed journal(Ref ref, DateTime? since) {
  final history = ref.watch(journalHistoryProvider(since));
  final versions = ref.watch(journalVersionsProvider(since));
  final stored = ref.watch(journalStoredProvider(since));
  final games = ref.watch(gamesProvider);
  final names = {
    for (final c in _v(ref.watch(allCharactersProvider))) 'characters/${c.id}': c.name,
    for (final p in _v(ref.watch(allPlacesProvider))) 'places/${p.id}': p.name,
    for (final i in _v(ref.watch(allItemsProvider))) 'items/${i.id}': i.name,
    for (final a in _v(ref.watch(allAllyFilesProvider))) 'allies/${a.id}': a.name,
    for (final s in _v(ref.watch(allServantFilesProvider))) 'servants/${s.id}': s.name,
  };
  final users = {for (final u in _v(ref.watch(allUsersProvider))) u.uid: u.displayName};
  final pages = {for (final p in _v(ref.watch(wikiPagesProvider))) p.id};
  final sources = <AsyncValue<Object>>[history, versions, stored, games];
  return JournalFeed(
    mergeLines([historyLines(_v(history), names), versionLines(_v(versions), pages), _v(stored), gameLines(_v(games), users)], since),
    partial: sources.any((s) => s.hasError),
    loading: sources.any((s) => s.isLoading),
  );
}
